## Design (before code)

- `native/scene` is a plain OBJECT/static helper module over **raw `flecs.h`**
  (no `EcsWorld` dependency — `ecs_world_t*` only), mirroring how
  `native/physics/src/transform_sync.cpp` looks up `LocalTransform` by name.
  Built-ins by id (`ecs_lookup` for `LocalTransform`, `ecs_lookup_path_w_sep`
  with `sep=""` for `Engine.Runtime.Camera/MeshRenderer/DirectionalLight`),
  user blobs via `ecs_get_type` + `ecs_get_type_info` + `ecs_get_id`
  (P3-03 snapshot bucket model in `editor_bridge.cpp`).
- **LocalTransform quirk (verified in ecs_world.cpp:42-48):** the built-in is
  registered under the bare name `"LocalTransform"` (no sep) — NOT
  `"Engine.Runtime.LocalTransform"`. Snapshot code (`editor_bridge.cpp`)
  treats it specially too. Scene save does the same: look up `"LocalTransform"`
  for the pose, skip the id from the generic blob sweep.
- Meshes: spec demands `mesh` = asset path + `#index`, never runtime
  `mesh_id`. Renderer owns no path table, so scene keeps a process-lifetime
  `scene_register_mesh_source(mesh_id, "assets/cube.glb#0")` registry
  (non-ABI-internal globals to skip the codegen type-map issue) with test-only
  fallback `mesh_id:<n>`. `scene_clear_mesh_sources()` resets between tests.
- ABI: `typedef int32_t (*EngineSceneSaveFn)(EngineWorld*, const char*);`
  + `EngineSceneLoadFn`, appended after `physics_world_for`, bump to 4.16,
  regenerate via abi_codegen (which already maps both C types used).
- JSON: in-module reader/writer, `std::to_chars` shortest round-trip floats,
  deterministic order (BFS by creation order + per-parent sibling tiebreak),
  file-local ids 1..N, `parent: 0` = root, `WorldTransform` skipped
  (derived), schema = FNV-1a32 of `name:size:align`, mismatch → skip + warn.
