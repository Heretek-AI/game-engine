## 2026-11-02 follow-up: FixedUpdate dispatch and a single clock

Review of #187 found two gaps: the generator mapped `Phase.FixedUpdate`
(5) to `"Update"`, and nothing dispatched by phase at all (phases were
only a doc comment on the runner); and there were two clocks (the
renderer advanced a native `Timestep` nobody read, while `Time.cs`
re-implemented the math with its own state). Fixed as follows:

- ABI 4.12 frame-clock tail (5 entries after the 4.11 audio tail):
  `system_set_phase`, `world_frame`, `time_set_scale`, `time_get_f64`,
  `time_get_u64`. `ENGINE_PHASE_*` values equal the C# `Phase` enum.
  If another tail lands on main first, renumber this one at merge time.
- The `EngineWorld` owns the only clock. `world_frame(world, wall_dt)`
  advances it and runs generic systems by phase: Startup (first frame
  only, dt 0), PreUpdate, Update, FixedUpdate once per fixed step with
  dt = 1/50 s, PostUpdate, Render. `systems_run` (4.2) is unchanged and
  still runs every system once.
- The renderer no longer advances its own timestep (`renderer_bridge.cpp`
  is back to main).
- `Time.cs` is now a view over the native clock: `Time.Frame(table,
  world, wallDt)` calls `world_frame`; every property reads native state.
- Generator: `PhaseName` maps 5 to `FixedUpdate`; `Register` emits one
  native system per phase plus `system_set_phase` (a plain Update system
  still emits the single `system_register` call).
- Tests: `engine_world_frame` (native, fake clock `[0.016, 0.016, 0.2,
  0.001]` gives FixedUpdate calls `[0, 1, 5, 0]` with dt 1/50 s, Update
  once per frame with the clamped dt, pipeline order, time_scale 0/2);
  `engine_illusion_sample` gains a generated `[UpdateInPhase(Phase.
  FixedUpdate)]` system driven through `Time.Frame`. HelloCube now runs
  its frame loop through `Time.Frame` with a fixed 1/60 s wall delta, so
  its golden is unchanged.
- No .NET SDK in the authoring sandbox: `NativeApi.g.cs` was edited to
  match the generator output by hand; the native files were syntax-checked
  with clang 18. CI is the full build and test run.
