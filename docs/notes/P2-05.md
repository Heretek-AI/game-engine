## 2026-11-03 — QA acceptance (t_29bffd94)

### Live diagnosis: kinematic sweep is silent in Jolt

- Prior run: phase-1 used MotionType=1 kinematic ball swept into the static
  floor (pose edit per step) → 0 kEnter, 0 kExit; sensor=1 and 0B/100-frames
  passed; native ctest 74/75 (engine_compositor_live failed via CollisionTests).
- Root cause (verified in source): Jolt emits no contact callbacks for
  kinematic-vs-static pairs, so the ring stays empty. `transform_sync.cpp`
  `push_to_physics` only pushes user-marked KINEMATIC links; statics never
  move and dynamics are sim-owned (never pushed — pushing would fight the
  solver). A kinematic sweep into a static floor is therefore the one
  combination that generates no OnContactAdded.
- Fix (managed test only, no native change): phase-1 uses a DYNAMIC ball
  (MotionType=2) dropped from y=5 — same scene as the P2-04 drop gate.
  Gravity sweeps the ball into the floor; impact fires exactly one
  OnContactAdded. Stop 5 steps after the first impact so the resting ball
  cannot bounce/roll into a second kEnter.
- Phase-2 (+3u exit): a Flecs pose-edit lift alone cannot separate a DYNAMIC
  body (pose push only applies to kinematic links; gravity re-impacts a
  teleported dynamic ball before separation registers). No entity-destroy
  ABI exists (only EngineEntityCreate/EngineEntitySet). In-ABI mechanism:
  collider-kind swap (sphere→box) — BodySystem::sync drops the Jolt body
  whose kind changed (RemoveBody+DestroyBody) and Jolt fires exactly one
  OnContactRemoved; the replacement box spawns at the lifted pose
  (SpawnPose reads LocalTransform), already separated, so no new kEnter.
  kExit records carry Jolt BodyIDs, so the count is global over the 10-step
  window (only floor+ball bodies exist in this phase → exact).
