#### JSON state-machine asset (proposal v1)

```json
{
  "name": "Locomotion",
  "initial": "Idle",
  "parameters": [
    {"name": "speed", "type": "float", "default": 0.0},
    {"name": "grounded", "type": "bool", "default": true},
    {"name": "jump", "type": "trigger"}
  ],
  "states": [
    {"name": "Idle", "clip": "idle", "loop": true},
    {"name": "Run", "clip": "run", "loop": true},
    {"name": "Jump", "clip": "jump", "loop": false}
  ],
  "transitions": [
    {"from": "Idle", "to": "Run",
     "duration": 0.25,
     "conditions": [{"param": "speed", "op": ">", "value": 0.5}]},
    {"from": "Run", "to": "Idle",
     "duration": 0.2,
     "conditions": [{"param": "speed", "op": "<=", "value": 0.5}]},
    {"from": "Run", "to": "Jump",
     "duration": 0.1,
     "conditions": [{"param": "jump", "op": "fired"}]}
  ]
}
```

- Parameter types: `float` | `bool` | `trigger`. Triggers are consumed
  (auto-reset) when a transition fires on them.
- Condition ops: float `> < >= <= == !=`; bool `==` (value true/false);
  trigger `fired`. All conditions in one transition are AND-ed; on
  multiple eligible transitions the listed order wins (first match).
- `duration` ≥ 0 seconds; 0 = cut. During a cross-fade the active pose is
  `BlendAnimPoses(from_pose, to_pose, eased_weight)` with both clips
  sampled at their own local times (non-looping `to` clip starts at 0 on
  entry; looping clips advance mod duration).
- Easing function (linear vs smoothstep) is the native task's call — record
  the choice here when made.
- Fail-closed: unknown clip/param name, missing `initial`, or malformed
  JSON fails the load (negative return, native log); never half-loads.
- `clip` names resolve against the P5-01/P5-02 `AnimClip` set already
  imported for the skin (no new clip format in this slice).

### Easing choice (contract decision for the managed test)

**Linear weight ramp**: `w = blend_pos / duration`. No smoothstep.
Exact step counts for a dt=0.05 driver (Idle→Run, duration 0.25):
fire-update (w=0, active still Idle) + 4 blend steps (w=0.2/0.4/0.6/0.8)
+ 5th update completes (blending=false, active=Run). Mid-fade golden:
at w=0.4 the run clip (y 0→2 over 2s) sampled at local fade time 0.1
gives y=0.1; blended `0*0.6 + 0.1*0.4 = 0.04` — asserted in the native
test. Managed test (t_edcbb944): assert these exact values, not ranges.

### `to`-clock semantics (subtle, assert exactly this)

The fire update's dt runs on the `from` clock; the `to` clip starts at 0
on entry, so only blend-step dts accumulate into `to` time. Jump fade
0.1s with dt=0.05: fire + 2 steps → `to` time = 0.10 (not 0.15).
