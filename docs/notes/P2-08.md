## 2026-11-04 — design (no new ABI, no new C++)
- Original game (no sample gameplay copied): straight ramp course of five
  static box slabs (start pad, lane, narrow bridge over a gap, lane, goal
  pad) + one kinematic sphere (marble, MotionType 1) + one static sensor
  box (goal, `IsSensor = 1`). No new assets/deps.
- Drive: `[UpdateInPhase(Phase.FixedUpdate)] MarbleController` (2-term
  proven shape `Tick(ref self, ref LocalTransform, float dt)`, like the
  IllusionSample Mover) integrates the pose at 6 m/s along a scripted
  vector (blended with live `Input.GetAxis("Horizontal"/"Vertical")`
  WASD/arrows/left-stick when held), applies scripted gravity, snaps to
  slab tops via `MarbleGame.IsGround`, falls through the gap. Kinematic
  push (`push_to_physics`) moves the Jolt body pre-step.
- Goal: collision drain (`Physics.CollisionEvents`) kEnter + sensor bit
  for marble/goal pair → prints literal `Finished in N s` once, where N is
  the controller's accumulated fixed-step time (3.6 s scripted).
- Respawn: host loop checks `local.Py < -10` per frame and restores
  `MarbleGame.StartPose()` (selftest proves y = -11 → start).
- Visual mode (`--frames`, hidden renderer, offscreen CI): uploads the
  HelloCube unit cube once; each slab gets a camera/light + propagate;
  same controller + drain loop; GPU-gated `[SKIP]` vs `[FAIL]` under
  `ENGINE_REQUIRE_GPU=1` per gotcha #2.
