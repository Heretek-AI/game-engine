Spike program (`/tmp/p502/spike.cpp`, scratch, not shipped) verified sampling math against P5-01 fixture constants:

```
$ g++ -O1 -o /tmp/p502/spike /tmp/p502/spike.cpp && /tmp/p502/spike
nlerp(0.5)= 0.0000 0.3827 0.0000 0.9239 |len|=1.0000
STEP t=0.75 holds prev key y=0 (next key y=1 at t=1)
cubicspline needs 3x values per key (in,val,out) per glTF spec
```

Findings:
- Fixture quats are (x,y,z,w): identity `[0,0,0,1]` -> 90°-about-Y `[0,sin45,0,cos45]`; nlerp at segment-midpoint gives a unit 45°-Y quat — LINEAR rotation sampling = nlerp + normalize (slerp optional later).
- STEP = hold previous key's value (t=0.75 between t=0 y=0 and t=1 y=1 yields y=0). Confirmed by P5-01 notes.
- Cubicspline channels carry 3x floats per key (in-tangent, value, out-tangent); importer already enforces `value_count == key_count * components * (3 if cubic else 1)`.
- Blend target: two sampled local poses (T/R/S per joint) lerped/nlerped by weight, then joint_matrix = global_pose * inverse_bind, uploaded as SSBO/push for `mesh.vert` 4-weight skinning.
