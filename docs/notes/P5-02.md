# P5-02 (sampling half): CPU clip sampling — linear / step / cubic-spline (#113)

## Design

New sampler lives in the assets module (host-side parse + sample code;
frame path never touches it yet — blending/GPU tasks consume it next):

- `native/assets/include/engine/assets/anim_sampling.hpp` — `AnimPose`
  (joint-major TRS flat arrays + `set[]` flags, all caller-owned),
  `AnimPoseReset`, `SampleAnimChannel`, `SampleAnimClip`.
- `native/assets/src/anim_sampling.cpp` — glTF 2.0 sampler semantics:
  STEP holds key `i`; LINEAR lerps T/S and slerps R (shortest path,
  lerp fallback near identity); CUBIC_SPLINE Hermites the segment with
  `m*dt`-scaled tangents and normalizes R. Clamps to end keys outside
  the range; empty/malformed/NaN/out-of-range inputs fail closed
  (untouched out, 0 joints). `noexcept`, no malloc/new on the path
  (linear segment scan, caller buffers only).
- No `engine_abi.h` change (pure native API, no bridge surface), so no
  ABI bump / regen.
- `native/tests/test_anim_sampling.cpp` (`engine_anim_sampling` ctest):
  STEP holds/clamps, LINEAR lerp + 45deg-Y slerp midpoint + segment
  pick, CUBIC_SPLINE Hermite hand values (0.15625 @ u=0.25, tangent
  0.25, dt-scaled 0.5) + rotation normalize, fail-closed gates,
  P5-01 `wave` fixture cross-check (rot 90degY + STEP +Y at t=0.5/1,
  identity reset of unset joint0, oob/malformed skip, NaN untouched).

## Discoveries

- `file(GLOB ASSETS_SOURCES ... *.cpp)`: new `anim_sampling.cpp` needs
  no CMake edit — only the test target was registered by hand.
- Test TUs build with `-Werror -Wc99-extensions`: C compound literals
  `(const float[]){...}` are rejected — use named `static constexpr`
  arrays.
- Test-side typo postmortem: a hand-written cubic rotation fixture had
  key1 value `(0,1,0,0)` instead of identity — sampler was right, the
  expectation data was wrong (1 FAIL -> fix data -> ANIM_SAMPLING_OK).

## For the blending task (done)

`SampleAnimClip(clip, t, pose)` is the consumed API: reset-then-sample
into caller buffers; `set[]` marks sampled joints. Two-clip blending
slerps/lerps two such poses by weight on top of this output. No bridge
surface exists — blending + joint-matrix upload stay native-side
(`PoseToJointMatrices` flattens straight into the `record_mesh_skinned`
joint-UBO payload), so no `engine_abi.h` change, no bump/regen.

# P5-02 (blending half): two-clip blending + bent-arm golden at t=0.5s (#113)

## Design

New code in the assets module (host-side, frame path untouched):

- `native/assets/include/engine/assets/anim_blending.hpp` /
  `native/assets/src/anim_blending.cpp`:
  - `BlendAnimPoses(a, b, w, out)` — per-joint lerp (T/S) + slerp (R,
    shortest path, normalized, identity fallback), weight clamped to
    [0,1], `set[]` OR-ed. `noexcept`, no malloc/new (caller buffers
    only); non-finite weight fails closed (out untouched).
  - `PoseToJointMatrices(pose, parents, inverse_bind, out, n)` — local
    TRS -> column-major mat4, parent-first compose (importer emits
    parents before children; forward/oob parent = root), then
    world * inverse_bind. Output is the `record_mesh_skinned` joint-UBO
    payload (n x 64B mat4s, `kSkinMaxJoints` cap enforced GPU-side).
- Golden: clip A = joint1 identity->90degY, clip B = joint1
  identity->90degX + STEP +X translation; at t=0.5s LINEAR sampling
  yields 45deg Y / 45deg X; blend w=0.5 gives T=(0.5,0,0) and
  R=slerp(45degY,45degX,0.5)=normalize(qA+qB). Joint matrices flatten
  with identity IBM; joint 1 is asserted against hand-derived values
  (computed with python3 math, NOT copied from implementation output).
- `native/tests/test_anim_blending.cpp` (`engine_anim_blending` ctest):
  27 checks — blend lerp/slerp, w=0/1 endpoints, clamp, NaN gate,
  hierarchy compose, inverse-bind cancel, fail-closed gates, golden
  setup pins (45deg samples, +X translation), golden joint1 matrix,
  2x64B UBO-payload shape.

No ABI change (pure native assets API consumed by the renderer-side
UBO upload path, same as the sampler half).

## Discoveries

- Nodiscard build gate: `SampleAnimClip` is `[[nodiscard]]`, so the
  test's `SampleInto` helper needs `static_cast<void>(...)` under
  `-Werror -Wunused-result`.
- Golden fixture design: a 3-key clip sampled at t=0.5 returns the
  middle key exactly (no slerp exercised); use 2-key clips so t=0.5
  is the segment midpoint. First golden run caught this in the setup
  pins, not the golden itself — the pins earned their place.
- Joint-major indexing: joint 1 translation lives at `to+3`, not `to`.
- LSP `pp_file_not_found` noise on the new headers is include-path
  configuration (build compiles clean); ignore.
- Golden constants (s=sin22.5deg, c=cos22.5deg, q=(s,s,0,2c)/|..|)
  were derived in python3 before the test was written; slerp equality
  slerp(qA,qB,0.5)=normalize(qA+qB) holds because both midpoints take
  the symmetric (equal-angle) path — verified by the passing golden,
  not assumed.
