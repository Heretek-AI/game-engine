# P5-01: Skeletal mesh + animation clip import (#112)

## 2026-11-01 — spike: cgltf skins + clips (P5-00 precedent)

- cgltf v1.15 (in-tree `_engine_cgltf-src`): skins expose `cgltf_skin`
  with `joints` (`cgltf_node**`), `inverse_bind_matrices`
  (`cgltf_accessor*`, MAT4 float16 per joint, `cgltf_num_components`=16);
  animations expose `cgltf_animation` with `samplers[]` (input=times,
  output=values, `interpolation` enum) + `channels[]` (sampler index,
  `target_node`, `target_path` enum).
- Enum order matters: the importer `static_cast`s
  `cgltf_animation_path_type` (invalid/translation=1/rotation=2/scale=3/
  weights) and `cgltf_interpolation_type` (linear=0/step=1/cubic_spline=2)
  directly into `AnimTargetPath` / `AnimInterpolation` — weights channels
  are skipped, never cast.
- Key reads via `cgltf_accessor_unpack_floats` (float-only; non-float
  accessors skip the channel, never fail the clip). Times must be finite
  and strictly ascending; value_count = key_count * components (T/S=3,
  R=4, x3 for cubicspline in/out/value tangents).
- Joint hierarchy is NOT in skin order: resolved by walking
  `cgltf_node->parent` chains to each joint's nearest ancestor that is
  also a joint of the same skin, then re-emitted parent-first (BFS) so
  `parent_index` always points at an earlier joint (-1 = root); cycles or
  unreachable joints fail closed (corrupt skin, no partial append). Clip
  `target_joint` indices resolve against that same parent-first order
  (cgltf slot -> emit index map), so they index the `.skel` joint array
  directly. Channels whose target node is not a joint of the selected
  skin are skipped; clips left channel-less are skipped
  (`skin_index` = 0 default).
- Fixture (`skeletal_glb_fixture.hpp`, generated not checked in): two-bone
  `.glb`, joint1 child of joint0, identity IBMs, one "wave" clip — joint1
  rotation LINEAR quats identity -> 90deg-Y -> identity at t=0/0.5/1,
  joint1 translation STEP +Y at t=0/1.
- GLB chunk-length gotcha (same as P5-00 §4.13.3): chunk Length = payload
  bytes only (`+8` -> `data_too_short`); the 6-byte u16 index run needs
  2 pad bytes so the u8 JOINTS_0 view starts 4-aligned; translation
  accessor is VEC3.
- Layouts: `.skel` magic "ENGS" v1, `.anim` magic "ENGA" v1 (LE, IEEE-754
  LE floats, readers bounds-check + fail closed on bad magic/version/
  truncation). Kinds 4/5 wired through engine-pak + ExportPipeline with
  per-kind sub-GUIDs. Test-only entry `SkeletalParseMemory` mirrors the
  worker map -> `cgltf_parse` -> load_buffers sequence in-memory.
- No `engine_abi.h` change (import lives in `engine_assets` + tooling),
  so no ABI bump or regen on this slice.

## 2026-11-02 — CodeRabbit on the new head (3 threads)

- 4438528020 (verified real): the skeleton-only success rule tested only
  `!r.ok`, so a `mesh artifact write failed` could be masked the same way
  as `no decodable triangles`. Fixed: explicit `no_triangles` flag set
  only in the no-triangles branch; the accept rule now requires it.
- 4438528024 (verified real): `SlotReorder` sat outside the
  `ENGINE_ASSETS_HAS_CGLTF` guard and outside the anonymous namespace
  (cgltf types + external linkage in a cgltf-less build). Fixed: moved
  inside guard + anonymous namespace; round-1 item 6099's claim is
  superseded for this function.
- 4438528028 (verified real): both parent walks in `SlotReorder` and the
  emit-loop recompute were unbounded — a parent cycle (cgltf_parse does
  not reject those) hangs the single-lane import worker. Fixed: both
  walks bounded by `data->nodes_count` steps; overlong chains return {}
  and the caller fails closed (`skeletal import failed`).
