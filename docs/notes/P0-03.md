# P0-03 Find and fix the `engine_audio_spatial` hang (#67)

- 2026-11-04 (this card): reproduced the hang — `engine_audio_spatial`
  runs 0.62 s solo but goes fully silent (zero output, then CTest 60 s
  TIMEOUT kill) under `ctest -j4`. Failure is flaky: 2 silent-timeout runs
  out of ~6x240 loop iterations on this box (loops 2-3 failed, loops 1/4/5/6
  clean at 240/240). Solo `until-fail:50` is 50/50; the hang needs parallel
  load (`-j4` with physics + gi_zero_bake in the same run).
- Root cause (same class as the 2026-10-31 e11e698 analysis, whose flags
  were lost when P5-06 #185 reworked `attach_file` for mixer-bus routing):
  `attach_file` uses `STREAM | ASYNC` WITHOUT `WAIT_INIT`, so init returns
  before the stream LOAD job parses the fixture header on the
  resource-manager job thread; teardown (`ma_sound_uninit` /
  `ma_engine_uninit`) posts FREE/QUIT behind the queued LOAD and blocks in
  `ma_resource_manager_inline_notification_wait()` until the starved job
  thread catches up — the observed silent 60 s hang.
- Fix (2 lines + comment, no RUN_SERIAL, no test weakening):
  `native/audio/src/audio_world.cpp` restores
  `MA_RESOURCE_MANAGER_DATA_SOURCE_FLAG_WAIT_INIT` to the attach flags
  (init itself becomes the bounded wait point; streaming/decode still
  async on workers); `native/tests/CMakeLists.txt` lowers the
  `engine_audio_spatial` TIMEOUT 300 -> 60 per the slice acceptance.
- Verified: `ctest --preset ci-linux -j4 --repeat until-fail:50 -R
  engine_audio_spatial$` 50/50 PASS (31.3 s, 31.2 s, 31.1 s runs);
  broad `until-fail:30 -R "engine_audio_spatial|engine_physics|
  engine_gi_zero_bake"` green repeatedly; full `ctest --preset ci-linux
  -j4` 79/79 PASS. One earlier flaky TIMEOUT was observed before this
  fix on the same box (loops 2-3 above); post-fix 50x3 + full-suite runs
  are clean. No gdb backtrace capturable: the hung process emits nothing
  and must be let to TIMEOUT-kill; the mechanism is documented from the
  miniaudio source path above.
