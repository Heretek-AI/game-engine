# P7-01: Windows GPU lane in CI (2026-11-01)

- Slice: P7-01 (issue #130). Depends on P7-00 (spec §4.15.3) and P1-05 (golden harness).
- Decision: **Lavapipe** (not SwiftShader). Same Mesa CPU-driver family as the
  Linux lane (§4.1–§4.3), so golden-tolerance behavior stays closest to Linux.
  Action used: `jakoch/install-vulkan-sdk-action@v1.7.0`, pinned by SHA
  `d17de7e2f5e50efb5d2123efed18497d3c58c533` (= `v1.7.0^{}`; the `v1` tag is a
  force-pushed moving tag verified to the same SHA on 2026-11-01), matching the
  existing `ilammy/msvc-dev-cmd@<sha> # v1` pinning style in `ci.yml`.
- Change (` .github/workflows/ci.yml` only, no slice code):
  1. New Windows-only step `Install Vulkan SDK + Lavapipe (Windows)` with
     `install_lavapipe: true`. The action registers the Lavapipe ICD
     (`C:\lavapipe\share\vulkan\icd.d\lvp_icd.x86_64.json`) in
     `HKLM\SOFTWARE\Khronos\Vulkan\Drivers` automatically — verified against
     the action README (Registering Lavapipe section), no manual `reg add`.
  2. New Windows-only step `Probe Vulkan device (Windows)`: `vulkaninfo
     --summary` with `VK_LOADER_DEBUG=error,warn`. This is the acceptance
     "Windows CI log shows a Vulkan device" — expect `llvmpipe (LLVM ...)`
     in the device list.
  3. `ENGINE_REQUIRE_GPU` now `1` on Linux **and** Windows
     (`(runner.os == 'Linux' || runner.os == 'Windows') && '1'`); macOS stays
     unset until P7-02 lands its MoltenVK/KosmicKrisp lane. Every
     `gpu_missing()` call site (§4.3 contract: FAIL, never SKIP) now runs live
     on Windows.
- Not changed: `SDL_VIDEO_DRIVER` stays `offscreen`-only-on-Linux at the job
  level, and the per-test `ENVIRONMENT "SDL_VIDEO_DRIVER=offscreen"` CTest
  properties in `native/tests/CMakeLists.txt` apply on Windows too — SDL's
  offscreen driver exists on Windows, hidden-window creation works headless,
  and Lavapipe advertises `VK_KHR_win32_surface` + swapchain (§4.15.3), so
  `engine_swapchain` presents and the P1-05 goldens run within tolerance.
- Managed job untouched: its live tests skip on "no native lib", which
  `ENGINE_REQUIRE_GPU=1` does not gate (only `gpu_missing` paths fail closed);
  no managed change needed for "no GPU test is skipped".
- Verification: YAML parses (`yaml.safe_load`, 10 native steps listed);
  full Windows proof comes from CI on the pushed branch (push triggers `ci`
  via `on: push, branches: ["**"]`). `vulkaninfo --summary` output and
  `No GPU test is skipped` are read from the windows-2025 job log.
