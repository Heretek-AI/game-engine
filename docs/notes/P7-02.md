# P7-02 macOS presentation via MoltenVK (#131)

- Date: 2026-11-01. Branch `parity/p7-02-macos-presentation-moltenvk`.
- P7-00 spike (§4.15.2) ground truth: macos-15 image ships no Vulkan SDK /
  MoltenVK / vulkaninfo; portability-enumeration extension + flag required
  regardless of driver (MoltenVK vs KosmicKrisp — P7-02 pins whichever the
  SDK-installed CI provides; do not assume `libMoltenVK.dylib`).
- `VK_KHR_portability_subset` lives in `vulkan_beta.h`, NOT `vulkan_core.h`
  (local libvulkan-dev 1.4.309): the device-side code uses a string literal
  with the macro only as an override, so Linux/Windows headers without the
  beta header still compile.
- MoltenVK validation-layer gap (spec warning, not an engine bug): MoltenVK
  does not load Vulkan layers itself; validation comes from the SDK loader
  (`enable_validation` path unchanged).
- (Superseded, see Outcome.) `humbletim/install-vulkan-sdk@v1.2` was first chosen over
  `jakoch/install-vulkan-sdk-action` for the macOS CI step: pinned
  `version: 1.4.309.0` (matches local libvulkan-dev 1.4.309 headers, so the
  beta-header layout above matches CI), `cache: true` for the ~1.75 GB SDK,
  exports `VULKAN_SDK` + `PATH` bin for FindVulkan/vulkaninfo.
- M3 feature gate risk on MoltenVK (unverified until the macOS CI log
  lands): `gpu_has_m3_features` requires BDA + descriptorIndexing +
  drawIndirectCount. MoltenVK advertises `bufferDeviceAddress` on Apple
  Silicon (Metal GPU addresses) but the full set is unproven — if CI shows
  "no suitable GPU", follow-up narrows the gate with a `portability_subset`
  relaxation, not a skip.
- Verified locally on Linux with Mesa RADV (an AMD GPU, not lavapipe;
  the CI Linux lanes use lavapipe): `SDL_VIDEO_DRIVER=offscreen
  ENGINE_REQUIRE_GPU=1 ./build/ci-linux/native/tests/engine_swapchain`
  prints the new `portability: enumerate=portability_enumeration
  device=AMD Radeon Graphics (RADV GFX1151)` line + `SWAPCHAIN_OK`;
  `engine_renderer_bootstrap` same line + `RENDERER_BOOTSTRAP_OK`.
  Linux behavior unchanged (no portability ext requested, subset count 1).

  Fixed with an `Export macOS Vulkan env` step that resolves the paths in

## Outcome (2026-11-01, review round 3)

- SDK 1.4.309.0 ships MoltenVK 1.2 (device apiVersion 1.2.296), so every
  GPU test skipped. humbletim v1.2 cannot unpack the `.app` macOS SDK zips
  LunarG ships since 1.4.313 ("unrecognized zip/layout"), so the macOS lane
  now installs 1.4.328.1 with the jakoch action (already pinned for
  Windows). The paravirtual device then reports apiVersion 1.4.323.
- MoltenVK there lacks only `drawIndirectCount`. No production path
  records a counted draw, so it is optional now (enabled when supported,
  reported via `features().draw_indirect_count`). `engine_gpu_indirect`
  records no counted draw without it: a draw outside a render pass with
  no pipeline is invalid usage that lavapipe tolerated and MoltenVK
  crashed on.
- Cocoa aborts when SDL events are pumped off the main thread (the live
  editor-server test drives `renderer_frame` from a worker). On Apple,
  `pump_events` returns "no events" off the main thread.
- MoltenVK timestamps coincide for a near-empty frame (0.000000 ms, same
  in the native gpu-timer test), so on macOS the live GPU-time check
  requires a resolved value (>= 0) rather than > 0.
- macOS CI now runs with `ENGINE_REQUIRE_GPU=1`: no GPU test skips there.
