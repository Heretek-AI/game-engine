## 1. Window usage

Open: **File > Build > Build Player** (`MainWindow.OpenBuildPlayerWindow`).
The window (`managed/Engine.EditorApp/BuildPlayerWindow.cs`, pure code-behind,
560×480) contains:

| Control | Name | Behaviour |
|---|---|---|
| OS selector | `OsSelector` | Windows / Linux / macOS → `BuildPlayerModel.TargetOs` |
| Config selector | `ConfigSelector` | Release (default) / Debug |
| Output folder box + Browse | `OutputDirBox` / `BrowseButton` | Text path or Avalonia `StorageProvider` folder picker |
| Build | `BuildButton` | `Model.BuildAsync(andRun: false)` |
| Build And Run | `BuildAndRunButton` | `Model.BuildAsync(andRun: true)`; launches player via injectable launcher |
| Progress bar | `BuildProgress` | 0..1 from builder `IProgress<double>` reports |
| Log view | `LogView` | `Model.LogLines` (start line, builder log, success/fail line) |
| Status | `StatusText` | `Model.StatusLine` |
| Cold boot | `ColdBootText` | `LastResult.ColdBootSeconds` formatted `cold boot {s:F2}s` |

State machine (`BuildPlayerModel`): Idle → Building → Succeeded | Failed.
Build buttons are disabled while Building and when no output folder is chosen
(`CanBuild`; validation message "Choose an output folder.").
Backend runs on a worker thread (`Task.Run`) so the UI thread never blocks;
progress callbacks marshal via `Dispatcher.UIThread.Post`.

`PlayerBuildController` (`managed/Engine.Editor/PlayerBuildController.cs`,
Avalonia-free) offers the same operations with richer reporting:
`BuildAsync` streams progress + log sinks, maps exceptions/cancellation to a
failed `PlayerBuildResult`, records `LastStatus`; `BuildAndRunAsync` builds
then launches, gating Run to the editor's own OS (`RuntimeTargetOs`) with a
`run: skipped (built X, editor runs on Y)` note for cross-OS targets, and
times the launch with a `Stopwatch` into `LastStatus.ColdBootSeconds`.
`RidFor`: Windows→`win-x64`, Linux→`linux-x64`, macOS→`osx-x64`.

## 3. Stub vs real backend

- **Current: `StubPlayerBuilder` (default).** Writes placeholder `player[.exe
  |.app]`, empty `game.pak`, `Game.dll` into `outputDir`, reports 0.0/0.5/1.0,
  returns `Succeeded: true` with log `stub build {os} {config}: backend not
  yet merged (P2-07 #85, P3-10 #96)` and `ColdBootSeconds: 0.0`.
- **Real backend:** P2-07 engine-player + `.pak` pipeline (#85, unmerged at
  time of writing; P3-10 #96 likewise open). Both `BuildPlayerModel` and
  `PlayerBuildController` accept any `IPlayerBuilder` via constructor DI, so
  the real backend plugs in with **no UI change** — same contract:
  `IPlayerBuilder.BuildPlayer(PlayerTargetOs, outputDir, PlayerBuildConfig,
  progress, ct)`.
