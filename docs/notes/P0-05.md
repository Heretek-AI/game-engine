# P0-05 Fix misaligned transform column storage (#145)

- Choice: keep `alignas(64)` and make the columns aligned, rather than lowering the alignment. Many components besides the transforms are `alignas(64)` (physics `RigidBody` and colliders, audio `AudioSource`/`AudioListener`), and their 64-byte sizes are part of the C ABI, so lowering would touch every module.
- Mechanism: Flecs v4.1.6 grows table columns with `ecs_vec_init(NULL, ...)` / `ecs_vec_append(NULL, ...)` (`flecs_table_grow_column`, `flecs_table_fast_append`), so with no allocator the storage comes straight from `ecs_os_api.malloc_/realloc_`. The existing M1-02 heap hooks return 64-byte-aligned payloads but were only installed by two tests. `EcsWorld::construct()` now calls the new `EnsureAlignedFlecsHooks()` before `ecs_init` and before the task hooks are written (installing defaults later would reset them). `FLECS_USE_OS_ALLOC` is not needed.
- `ecs_os_set_api` is one-shot per process. If some code calls `ecs_init` with the stock allocator before the first `EcsWorld`, the hooks cannot be installed. `EcsWorld::aligned_hooks()` reports that, and `EcsWorld::bulk_create` / `ApiWorldBulkCreate` check the Local column base and return 0 instead of faulting.
- Repro before the fix (GCC 13.3, `ci-linux-gcc`, lavapipe): `engine_gpu_indirect` SIGSEGV at `EcsWorld::bulk_create+137: vmovaps %ymm0,(%rax)`.
- Acceptance: `engine_ecs_column_alignment` prints `[PASS] ecs: Local column 64B-aligned` for 1, 7 and 10 000 entities. Clang `ctest --preset ci-linux`: everything passes except `engine_export_publish_aot` and its dependents, which is the P0-04 environment-only NETSDK1047 failure from the Ubuntu source-built SDK used locally.
